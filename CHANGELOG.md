# История изменений

## 2026-10-26 — 0.3.5: вложенные категории и обновления

- Подкатегории на сайте и в Windows: вложенный список, выбор родителя, фильтрация всей ветки, сохранение детей при удалении родителя.
- Иерархия включена в зашифрованный обмен Python/JS; циклы и отсутствующие родители не приводят к потере категорий. Для обмена требуется 0.3.5 на обеих сторонах.
- В Windows управление категориями перенесено в ПКМ. Внизу слева оставлены настройки; операции хранилища перенесены внутрь настроек. Дублирующая блокировка и отдельный генератор удалены из боковой панели.
- Добавлена проверка стабильных GitHub Releases при запуске и вручную. Новая версия открывается в браузере после выбора пользователя; автоматической установки нет.
- Проект подготовлен как публичный Git-репозиторий с сохранением All Rights Reserved для собственного кода.
- Проверки и сборка: [протокол 0.3.5](docs/release-0.3.5.md).

## 2026-10-26 — уточнения интерфейса 0.3.4

- После кнопки ручной синхронизации добавлен отступ в одну строку.
- Уведомления справа внизу используют оранжевый текст; успешный обмен сообщает «Синхронизация выполнена!».
- В просмотре скрываются пустые поля и неназначенная категория; при редактировании все поля доступны.
- Файл установщика теперь называется `PasswordsManager.exe`.

## 2026-10-26 — 0.3.4: просмотр, категории и варианты установки

- Уведомления «Синхронизация..» / «Готово» справа внизу; ошибки заменяют сообщение ожидания.
- В настройках ручная синхронизация перенесена под интервал, сохранение — вниз, галочка автоматического обмена — вправо от текста.
- Просмотр записей с отдельным переходом к редактированию; блокировка доступна сверху без выбранной записи, включая мобильный веб-интерфейс.
- Явное удаление категорий с сохранением записей, выбор цвета с фиолетовым по умолчанию. Цвет хранится в локальных зашифрованных настройках и экспорте.
- Настольный вход Google через комплектный Desktop OAuth-клиент; на новом профиле — открытие версии из Drive с проверкой мастер-пароля. Токены защищены DPAPI, веб-клиент не содержит Desktop credentials.
- Setup.exe для текущего пользователя, ярлык меню «Пуск», регистрация удаления; данные в AppData сохраняются при удалении. Отдельный portable ZIP с `portable.flag` и собственной папкой `data`.
- Проверки и границы приёмки: `docs/release-0.3.4.md`. Реальный вход Google и установка/удаление в Windows этой сборкой не выполнялись.

## 2026-10-25 — Web 0.3.1 / Windows 0.3.3: вся корзина и независимый генератор

- В разделе корзины добавлена очистка всех удалённых записей за одно подтверждение и одну запись состояния. Поиск не ограничивает очистку; активные записи сохраняются, для удалённых остаются tombstones. Отмена не меняет данные.
- Генератор больше не записывает настройки в хранилище и не ставит изменения в очередь Google. На сайте генерация выполняется без RPC к шифрующему Worker, записи файла и сетевых запросов; в Windows — без commit хранилища. Настройки запоминаются только в памяти текущего запуска/вкладки.
- Генерируемые пароли попадут в хранилище и обычную очередь обмена только после явного сохранения записи. Старые поля настроек генератора остаются читаемыми для совместимости, но новым генератором не используются.
- Проверены массовая очистка с поиском и отменой, сохранение активных записей, отсутствие сетевых/дисковых вызовов генератора и работа генерации при имитированном офлайне.
- В списке облачных копий полные checkpoint-файлы показываются перед служебными версиями. Случайный UUID версии больше не выдаётся за порядок её свежести.

## 2026-10-25 — Web 0.3.0 / Windows 0.3.2: расписание и оптимизация Drive

- В настройках доступен автоматический обмен с интервалом 1–1440 минут (по умолчанию 5) либо режим только ручной синхронизации. Ручная кнопка работает независимо от расписания.
- Сохранение записи, категории и настроек сайта больше не отправляет данные немедленно. Неотправленные изменения отмечаются; до обмена они существуют в памяти вкладки. Первоначальное создание самого облачного хранилища выполняет первую загрузку.
- Настройка sync_minutes хранится зашифрованно; 0 означает только ручной обмен. Windows 0.3.2 принимает это поле и учитывает интервал. Старые Windows-сборки могут отклонить экспорт с этим новым необязательным полем.
- Убраны повторные полные загрузки в одной операции. Между обменами кешируется только шифротекст с проверкой серверной версии файла; изменённые и новые версии скачиваются, исчезнувшие удаляются из кеша. Одновременно выполняются максимум четыре загрузки.
- Сохранены полное чтение списка, лимиты, обнаружение дублей и чтение публикации обратно. Копия очереди перед публикацией уже содержит пользовательские данные; вторая копия только ради сброса pending не создаётся.
- В имитации с 10 файлами истории сценарий сократился с 53 до 19 запросов (43 → 12 скачиваний). Это не измерение настоящей сети Google. Скрипт: `web/password-manager/scripts/benchmark-drive.mjs`.

## 2026-10-25 — Web 0.2.2: блокировка по бездействию и подключение Google

- Убрана немедленная блокировка при visibilitychange: сворачивание браузера и переключение вкладки не требуют мастер-пароль до срока бездействия.
- Таймер учитывает время в фоне и проверяется при возвращении до сброса времени активности. Ручная блокировка сохраняется.
- Действующее подключение Google отделено от доступа к хранилищу: блокировка отменяет запросы и незавершённый вход, но не очищает действующий access token. Явное отключение Google по-прежнему очищает его.
- Убран принудительный prompt=select_account. Перезагрузка и срок действия токена Google всё ещё могут потребовать повторного подключения; refresh token в браузер не сохраняется.
- Проверки используют настоящее скрытие окна Chromium и управляемое время 29/31 минут, отдельно проверяют сохранение Google-подключения.

## 2026-10-25 — Web 0.2.1: исправление контекста fetch

- Исправлена ошибка браузера `'fetch' called on an object that does not implement interface Window.` при обращении к Google Drive: сетевой метод привязан к globalThis вместо объекта транспорта.
- Регрессионный тест воспроизводил точное сообщение до исправления и проходит после него. Проверка интерфейса дополнена настоящим браузерным fetch к собственному localhost-ресурсу без имитации fetch и без обращения к Google.
- OAuth-клиенты и формат хранилища не менялись. Для применения нужно обновить файлы Cloudflare, затем перезагрузить страницу.

## 2026-10-25 — 0.3.1 и настройка Google OAuth

- Пользователь предоставил два OAuth Client ID. Проверены скачанные Desktop/Web JSON: общий проект, корректный тип клиента и разрешённый origin Cloudflare.
- Web Client ID включён в сайт; техническое поле ввода ID заменено кнопкой входа Google. Client secret в сайт не копируется.
- Windows принимает официальный legacy auth_uri из Google Desktop JSON; сам OAuth-запрос по-прежнему отправляется только на фиксированный Google v2 endpoint. Добавлена проверка против подмены домена.
- Реальный вход, consent, Drive API enablement и test users требуют проверки в аккаунте; проверка JSON не выдаётся за успешное подключение.
