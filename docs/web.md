## Первый запуск

Повторена логика [Obsidian Vault switcher](https://obsidian.md/help/manage-vaults): создать новое или открыть существующее, затем название и расположение. Использованы собственное оформление/значок и адаптивный русский интерфейс с тёмной и светлой темами.

Для нового хранилища:

1. Имя и расположение: зашифрованная копия в браузере либо папка, если браузер поддерживает её выбор.
2. Мастер-пароль 8–128 Unicode-символов и повтор, без обрезки пробелов.
3. Показ отдельного 52-символьного ключа восстановления, явное копирование/скачивание и обязательное подтверждение сохранения.
4. Только после подтверждения — сохранение зашифрованного файла/IndexedDB и переход к записям.

При отсутствии API выбора папки предлагается скачивание файла. Это реальное ограничение [File System Access API](https://developer.mozilla.org/en-US/docs/Web/API/Window/showDirectoryPicker), а не подставленный путь. Браузерная копия и файл имеют отдельные результаты записи; изменённый извне файл не затирается.

## Функциональность и защита

Веб-версия создаёт и открывает PMVAULT v1, редактирует записи, ищет, создаёт категории, генерирует пароли, работает с корзиной и экспортом. Есть блокировка при бездействии/уходе со вкладки, зашифрованный черновик, восемь локальных состояний и восстановление доступа с обновлением локальной истории. Метаданные списка хранилищ (имя/время/handle) открыты локально; поля записей зашифрованы.

Argon2id выполняется в Worker через локально включённый `hash-wasm` 4.12.0; параметры совпадают с Python. AES-GCM — Web Crypto, AAD/nonce/соль/обёртки/UTF-8/Base32 совместимы с Windows. Проверены кириллица и emoji, переходы через обычную смену мастер-пароля, восстановление и сохранение причинного состояния sync. Сервер получает статические запросы, не содержимое хранилища. Аналитики, CDN и внешних шрифтов нет. Dependency MIT-текст включён рядом с библиотекой. Источники API: [hash-wasm](https://github.com/Daninet/hash-wasm), [Web Crypto](https://developer.mozilla.org/en-US/docs/Web/API/SubtleCrypto/encrypt).

Запись устроена как stage в Worker → атомарный IndexedDB commit → подтверждение Worker. Ошибка диска не подменяет рабочую модель неподтверждёнными данными. Счётчик последовательности в readwrite-транзакции предотвращает перезапись устаревшей вкладкой. Ключи в localStorage/URL/журналы не записываются. При блокировке DOM очищается и Worker завершается.

## Проверки

- Шесть Node-тестов: генератор, границы 7/8/128/129 и Unicode, неверный пароль, recovery, nonce, маркеры открытого содержимого, дубликаты JSON/ошибки кодировки/лимиты KDF/повреждение, реальный цикл Python → JS → Python и causal state desktop-файла.
- 15 браузерных сценариев: первый экран, 7-символьный пароль, несовпадающий повтор, ключ/обязательный checkbox, создание с восьмью символами, редактор/маска пароля, lock, неверный пароль/черновик, reload, выбор сохранения/отмены, генератор, восстановление с историей, мобильный вид, импорт desktop-файла через UI-handler и конкурентные вкладки с сохранением незавершённого ввода.
- Снимки проверены на 1440×920 и 390×844; горизонтального переполнения нет. Профиль браузера только тестовый, данные вымышленные. Браузер пользователя/авторизации/его clipboard не использовались.
- Встроенный Browser не запустился из-за отсутствующего `browser-service.mjs` в пути его runtime. Проверка выполнена в изолированном QtWebEngine Chromium на собственном localhost. В логах Qt есть сообщения о GPU fallback, но DOM/рендер/криптография и сценарии пройдены; JS runtime errors в отчёте отсутствуют. Нативный file picker при импорте заменён собственным File-fixture; реальная запись выбранной папки, clipboard-права, Safari/Firefox и hosted UI отдельно не приняты.

Локальные доказательства: `web/password-manager/artifacts/browser/result.json`, семь PNG и `source-manifest.json`; они исключены из Git/статической публикации и не переносят тестовый ключ восстановления на сайт. Приватная публикация фиксируется отдельно в `artifacts/web-deployment.json` после подтверждения Sites.

## Границы первого этапа

Google Drive в веб-версии пока не подключён: OAuth-проект по-прежнему не создан. Настройки прямо сообщают это. Полное разрешение конфликтов, импорт прежнего открытого JSON, переименование/удаление категорий и аварийная смена ключа восстановления остаются дальнейшими этапами; связанные действия доступны в Windows-версии. Полноценной приёмки веб-менеджера для настоящих паролей и независимого аудита нет.

Очистка данных сайта удаляет локальные копии; сохраняйте зашифрованный экспорт отдельно. Одинаковый адрес сайта и браузер важны: localhost и опубликованный HTTPS имеют разные IndexedDB. Компрометация самого кода хостинга/ОС/расширений может раскрыть ввод и память, даже при локальном шифровании. Браузер может запретить фоновую очистку буфера; чужое содержимое при этом не стирается.
