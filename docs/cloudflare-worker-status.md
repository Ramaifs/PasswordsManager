# Cloudflare Worker: состояние переноса

Пользователь сообщил адрес https://password-manager-vault.masaoyhs.workers.dev.
2026-10-25 по HTTPS получен HTTP 200 с подготовленной заглушкой. Это Worker,
а не Pages; создавать второй проект для смены суффикса не требуется.
Основное приложение на этом адресе ещё не подтверждено. Заглушка была доступна
без авторизации; закрытый доступ пока не подтверждён.

Пользователь позже разрешил оставить сайт публичным и пропустить Access.
Закрытие доступа сейчас не является условием загрузки. Настройка ниже сохранена
только как необязательная инструкция:

1. Workers & Pages → password-manager-vault → Access.
2. Protect this Worker behind Access → All traffic.
3. Authentication policy: разрешить только собственный email, без Everyone/Bypass.
4. Apply Access. Проверить адрес в приватном окне: до загрузки страницы требуется вход.

Этот режим защищает production и preview. Новый пакет Web 0.2 для существующего
Worker — `artifacts/cloudflare-workers-upload.zip`; прежний
`artifacts/cloudflare-pages-upload.zip` обновляется как совместимый путь к тем же байтам.
Фактическая загрузка приложения и перенос пользовательских хранилищ не выполнены.
Настройки авторизованного аккаунта из текущей инструментальной сессии недоступны.

Повторное чтение публичных `index.html`, `app.js`, `storage.js` при подготовке
Web 0.2 завершилось тайм-аутами; это не доказывает ни остановку сайта, ни обновление.
Результат записан в `artifacts/cloudflare-public-check.json`. Текущий ZIP подготовлен
локально и в аккаунт Cloudflare этой сессией не загружен.

Прежняя инструкция Pages в `cloudflare-migration.md` сохранена как история
подготовки; для существующего адреса использовать Worker, указанный здесь.

Источник: https://developers.cloudflare.com/workers/configuration/cloudflare-access/
