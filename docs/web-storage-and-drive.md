# Web 0.36: именованные хранилища, файл и Google Drive

Новые хранилища не сохраняются в постоянную базу браузера.
Новые зашифрованные хранилища не записываются ни в IndexedDB, ни в cookies,
ни в localStorage. Публичный Web OAuth client ID задан в исходниках;
пользователь нажимает «Войти в Google», не вводя технические настройки.

## Файл на ПК

После создания можно выбрать файл для сохранения через File System Access API,
если он поддерживается. SHA256 предыдущего файла проверяется перед записью:
внешние изменения не перезаписываются. При отказе прав, ошибке диска или
отсутствии API предлагается скачивание зашифрованного `.pmvault`.

Скачивание не считается доказательством записи на диск: статус продолжает
напоминать о сохранении файла. Закрытие вкладки с неподтверждённой записью
вызывает стандартное предупреждение браузера. Данные, история из восьми
состояний и файловые handles существуют в памяти вкладки, поэтому после
перезагрузки нужно заново открыть файл. Сворачивание и уход на другую вкладку
не вызывают немедленную блокировку. Блокировка происходит вручную или после
заданного бездействия (по умолчанию 30 минут), включая время в фоне. При возвращении
проверяется срок, даже если браузер приостанавливал таймеры. Блокировка удаляет
расшифрованные данные; зашифрованная сессия остаётся в памяти до закрытия.

## Drive

В Web 0.3.1 генератор не изменяет хранилище: его настройки и результат существуют
только в памяти вкладки, генерация не вызывает сетевые запросы или шифрующий
Worker. Лишь явное сохранение записи с выбранным паролем создаёт изменение для
обычного обмена. «Очистить корзину» удаляет все записи в корзине после подтверждения
одной операцией, включая скрытые поиском; для них сохраняются tombstones.

В Web 0.3 расписание задаётся в настройках: автоматический обмен с интервалом
1–1440 минут либо только вручную. По умолчанию — каждые 5 минут. Сохранение записи
не вызывает запросы Drive; до обмена изменения помечены как неотправленные и
существуют в памяти вкладки. Первое создание самого облачного хранилища загружает
его сразу, последующие записи и настройки отправляются по расписанию или кнопкой.
Таймер учитывает прошедшее время, не запускает несколько обменов параллельно,
не вмешивается в несохранённый редактор и открытый диалог. После ошибки повтор
происходит через выбранный интервал. Настройка хранится зашифрованно как
sync_minutes (0 — вручную); для таких экспортов нужна Windows 0.3.2.

Вход через Google Identity Services, scope `drive.file`. Access token существует только в памяти. При настроенном [Cloudflare Worker](../deployment/cloudflare-worker/README.md) сессия на срок до 30 дней восстанавливает подключение после перезагрузки и обновляет access token без нового окна входа. Refresh token хранится в зашифрованном серверном KV, идентификатор сессии — в HttpOnly cookie. Блокировка останавливает запросы, но не завершает Google-сессию. Отключение Google удаляет сессию. Без Worker сохраняется прежний браузерный вход с ограниченным сроком. Client secret не передаётся в браузер.

Протокол общих версий совместим с Windows: AES-GCM-конверт PMVAULT,
`protocol: 1`, причинные multivalue-регистры, идентичные `pm_app`, `pm_object`,
`pm_version`. Имя файла содержит имя хранилища и время UTC, например `Main-Backup-2026-10-25-15:21:50.pmvault`. Связь объекта с ID исключает пользовательские копии из протокола.
Нужны один аккаунт и OAuth-клиенты одного Google Cloud проекта. Разные хранилища разделяются по UUID конверта и метаданным `pm_vault`.
Чужой ключ/хранилище или удалённая закреплённая папка останавливают публикацию.

Перед отправкой прочитывается полный ограниченный список облачных версий;
публикация подтверждается чтением и побайтовым сравнением файла. При повторе
сначала отправляются ровно те же байты ожидающей версии. Конкурирующие изменения
сохраняются как варианты; в настройках Drive есть явный выбор варианта с
изначально скрытым паролем. Настройки и черновики не входят в общий причинный
поток Windows.

Для открытия веб-хранилища из Drive сохраняются также неизменяемые зашифрованные
полные копии `pm_checkpoint`. Они содержат настройки/черновики веб-сессии,
игнорируются протоколом Windows и позволяют восстановить очередь после
перезагрузки. Список Drive позволяет открыть такую копию либо общую версию Windows.
Копия до отправки сохраняет все пользовательские данные и точную очередь.
После подтверждения не создаётся ещё одна полная копия только ради удаления
флага pending: повтор старой очереди безопасно подтверждается чтением версии.
Отдельная копия по-прежнему создаётся для изменённых настроек/черновиков без
новой общей версии. При открытии checkpoint с очередью интерфейс отмечает её
как ожидающую обмена.
Имена облачных файлов содержат время и ID хранилища, не названия аккаунтов/пароли.

Веб-история не очищается автоматически. Списки ограничены 2000 объектами,
общий поток — 1000 версиями / 64 МиБ / 4 МиБ на версию; при превышении обмен
останавливается. Полная копия ограничена 16 МиБ. Это ограниченная реализация,
а не неограниченное архивирование. Удалять облачную историю автоматически
или восстанавливать пропавшую папку без решения пользователя приложение не будет.

При сети, недоступной до сохранения копии/очереди, изменения остаются только
в памяти вкладки. Интерфейс не называет это успешным сохранением. Перед закрытием
повторите отправку или скачайте `.pmvault`. Отключение Google предлагает локальную
копию и очищает токен; файлы в Drive и согласие Google автоматически не удаляются.
После восстановления/смены мастер-пароля старые облачные версии могут потребовать
явного объединения доступа через Windows; они не перезаписываются молча.

## Старые браузерные хранилища

На прежнем origin показан отдельный блок экспорта старой IndexedDB.
Доступ к ней используется только для чтения/экспорта и отдельно подтверждённого
удаления прежней копии. Новые состояния туда не записываются. Удаление после
скачивания не происходит автоматически: факт завершения скачивания не доказывает,
что пользователь сохранил пригодную копию. При смене домена открывайте прежний
адрес для экспорта; новый origin не может читать его IndexedDB.

## Проверка

16 Node-тестов проверяют криптографию, обмен Python ↔ JavaScript, очередь,
конфликты, чужой доступ, имитацию Drive, отмену/истечение входа и отсутствие
IndexedDB в новом хранилище. Проверка интерфейса в отдельном Qt Chromium
использует вымышленные данные, файловый handle-fixture и имитацию Google API.
Реальный OAuth, нативный системный выбор файла, физический диск через браузер,
публикация обновления на Cloudflare и два реальных клиента не подтверждены этими
проверками. Для настоящего входа сначала выполните [настройку OAuth](google-setup.md).

Для ускорения транспорт повторно использует полный список текущей операции,
а между операциями — только шифротекст неизменившихся серверных ревизий.
Метаданные перечитываются; изменение version приводит к новой загрузке,
удалённые файлы исключаются из кеша. До четырёх загрузок выполняются одновременно.
[Google описывает version как возрастающий номер каждого изменения](https://developers.google.com/workspace/drive/api/reference/rest/v3/files).
Кеш существует в памяти и очищается при смене/отключении Google. Проверка
подлинности шифротекста и обратное чтение новой публикации сохранены.

Первичные источники:

- [Google: token model](https://developers.google.com/identity/oauth2/web/guides/use-token-model).
- [Google: client ID, origins и CSP](https://developers.google.com/identity/gsi/web/guides/get-google-api-clientid).
- [Google: appProperties](https://developers.google.com/workspace/drive/api/guides/properties).

## Удаление

Из списка сайта удаляется только копия текущей вкладки. Отдельное подтверждённое удаление из Drive охватывает служебные версии и checkpoint-копии выбранного UUID. Перед удалением проверяется полный список и UUID в конвертах. Ручные копии исключены привязкой object ID; файлы на ПК и другие хранилища сохраняются.
