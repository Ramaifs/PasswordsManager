# Подготовка Google Drive для Windows и сайта

Пользователь создал проект и предоставил Desktop/Web Client ID. Скачанные JSON
проверены локально: типы клиентов корректны, проект общий, origin сайта разрешён.
Реальное подключение и согласие Google пока не проверены. Публичные ID сохранены
в `deployment/google/oauth-clients.json`; секреты остаются в исходных файлах Downloads.

## Доступ через разрешение без платёжной карты

Для пользователя подключение выглядит как «Войти в Google → разрешить доступ
к файлам приложения». Это OAuth consent. Пользователь не создаёт свой Cloud
проект, не вводит API key и не привязывает карту. Разработчик один раз регистрирует
само приложение: общий проект и отдельные Desktop/Web OAuth client ID.

Для небольшого стандартного использования Drive API платёжный аккаунт не нужен:
Google описывает billing как отдельный необязательный шаг создания Workspace
проекта, а стандартные обращения Drive API — без дополнительной платы.
Не проходите регистрацию Free Trial / создание Billing account только ради OAuth.
Открывайте [форму создания проекта](https://console.cloud.google.com/projectcreate),
затем [Drive API](https://console.cloud.google.com/apis/library/drive.googleapis.com)
и [Google Auth Platform](https://console.cloud.google.com/auth/overview).
Дополнительные проверки аккаунта зависят от настроек Google Cloud.

Оговорка актуальности: в 2026 Google изменил квоты и объявил платное превышение
стандартных порогов с предварительным уведомлением. Это не основание обещать
безлимитный бесплатный API. Источники:
[создание проекта, billing optional](https://developers.google.com/workspace/guides/create-project),
[стоимость и лимиты Drive](https://developers.google.com/workspace/drive/api/guides/limits),
[пользовательское разрешение OAuth](https://developers.google.com/identity/oauth2/web/guides/use-token-model).

## Настройка разработчиком

1. В Google Cloud создайте один проект разработчика для приложения и включите Google Drive API.
2. Настройте OAuth consent screen, название приложения и контактные данные. Для пробного проекта с внешней аудиторией внесите используемые Google-аккаунты в test users. Проверьте действующие ограничения Testing/время жизни разрешений до выпуска.
3. Создайте OAuth client ID типа **Desktop app**. Скачайте JSON. Один и тот же OAuth-проект/клиент используется на компьютерах, которые должны видеть файлы этого приложения.
4. Откройте разблокированное приложение → Синхронизация → Google Drive → Подключить Google. В версии 0.3.4 Desktop-клиент уже включён в сборку: подтвердите доступ в системном браузере, выбирать JSON не нужно. На пустом профиле кнопка «Войти через Google Drive» открывает существующую облачную версию после ввода её мастер-пароля.
5. Запрос приложения ограничен `https://www.googleapis.com/auth/drive.file`. Токены и локальная привязка папки сохраняются через DPAPI. Токены не входят в экспорт хранилища или ZIP приложения.

## Веб-клиент

В том же Google Cloud проекте создайте второй OAuth client ID типа **Web application**.
В Authorized JavaScript origins добавьте точный origin сайта:
`https://password-manager-vault.masaoyhs.workers.dev`.
Для локальной проверки можно добавить `http://localhost` и `http://localhost:4173`.
Redirect URI для GIS token popup не требуется. Не используйте Desktop client ID
вместо Web client ID и не вставляйте client secret в сайт.

В обновлённом сайте Web client ID уже настроен. Откройте Google Drive на начальном
экране или в настройках и нажмите «Войти в Google». Для создания выберите расположение Google Drive; для
существующего — «Открыть из Drive». Можно открыть `.pmvault` Windows и выбрать
«Сохранить и синхронизировать» с тем же аккаунтом и проектом.

Внешняя Testing-аудитория должна включать используемый аккаунт в test users.
При отказе Google принять домен/branding требуется выполнить требования консоли;
готовность проекта ещё не проверена реальным входом. Приватные
`appProperties` и доступ `drive.file` требуют общего проекта для двух клиентов.
Один Google-аккаунт/папка протокола сейчас рассчитаны на одно общее хранилище.

Блокировка хранилища не отключает Google. При сворачивании сайт не блокируется
до истечения заданного бездействия. Доступ Google существует в памяти вкладки;
после перезагрузки или истечения токена повторите подключение. Пользовательские
секреты Google сайт не запрашивает, используются только окна провайдера.
Браузерная синхронизация и сохранение копий описаны в [текущем статусе](web-storage-and-drive.md).

В коде фиксированы официальные OAuth endpoints, используется PKCE S256, случайный state и локальный callback `127.0.0.1` со случайным портом. Callback принимает только правильный state/Host/path, журнал HTTP отключён. Браузер закрывается пользователем, пароль Google приложение не принимает. Отмена/истечение трёх минут оставляют локальное хранилище доступным.

Drive хранит видимую папку «Менеджер паролей». Файлы — самостоятельные зашифрованные версии, не открытый JSON записей. Для подтверждения создания выполняется обратное чтение файла. Транспорт обрабатывает страницы списка, отказывается от incompleteSearch, ограничивает размеры и не переносит Authorization через HTTP-redirect.

Для живой приёмки нужны два независимых профиля/компьютера и только вымышленные данные. Проверьте: отказ авторизации, подключение, повторную авторизацию/обновление токена, раздельные изменения, конфликт пароля, удаление против редактирования, офлайн-возврат, смену ключей, прерванную публикацию, очистку истории, ручную копию, удалённую папку и отключение. Фиксируйте отдельно от имитации API. Наличие JSON само по себе не подтверждает настройку consent screen, Drive API или доступ тестовых пользователей.

Источники для актуализации настройки: [Desktop OAuth](https://developers.google.com/identity/protocols/oauth2/native-app), [Drive scopes](https://developers.google.com/workspace/drive/api/guides/api-specific-auth), [uploads](https://developers.google.com/workspace/drive/api/guides/manage-uploads), [ошибки API](https://developers.google.com/workspace/drive/api/guides/handle-errors).

## Сохранение веб-сессии

Для автоматического продления входа и восстановления после перезапуска браузера используйте [серверные сессии Cloudflare Worker](../deployment/cloudflare-worker/README.md). Client secret находится только в секретах Worker. При статическом размещении остаётся короткая браузерная сессия.
