# Протокол синхронизации v1

Реализация: `sync_state.py`, `sync.py`, `drive.py`, `oauth.py`, `protected.py`, `sync_ui.py`. До реального Drive выполнены собственные тесты с вымышленными данными. Формального доказательства или независимого аудита нет.

## Причинные состояния

Каждая запись и категория — отдельный многозначный регистр. Вариант имеет уникальную точку `UUID-актора:счётчик`. Глобальный вектор хранит максимальные наблюдавшиеся счётчики. Актор случайный для каждой сессии приложения, не переносится через экспорт; копирование профиля не должно создавать одинаковые новые точки.

С 0.38 цвет категории передаётся регистром `category_color:<uuid>` со значением `#RRGGBB` или null (сброс). Иерархия передаётся регистром `category_parent:<uuid>`. При открытии версии проекция восстанавливает цвета в `settings.category_colors`, а локальные тему, автоблокировку и черновики сохраняет. Если в прежнем хранилище уже есть локальный цвет, но его регистра ещё нет, следующая синхронизация добавляет его новой причинной точкой. Наличие null-регистра исключает повторную миграцию сброшенного цвета. Цвета удалённых категорий в представление не переносятся. Конкурентные разные цвета требуют явного выбора. Старым клиентам, не знающим category_color, требуется обновление до 0.38.

Локальное изменение заменяет наблюдавшиеся варианты регистра новой точкой. При слиянии общие точки остаются; односторонняя точка остаётся, если другой вектор её ещё не наблюдал. В противном случае она была причинно заменена. Одинаковая точка с другим значением/регистром отклоняется. Объединение векторов — максимум компонент. Проверены идемпотентность, коммутативность и ассоциативность на собственных ветвящихся сценариях; это тесты, не исчерпывающая верификация CRDT.

Несколько одинаковых значений не требуют выбора, но их точки сохраняются. Несколько разных значений считаются конфликтом; часы не выбирают победителя. При конфликте сохраняется прежнее локальное представление, если оно было, а все варианты доступны через отдельное действие. Обычное редактирование конфликтующего регистра отклоняется. Подтверждённый выбор создаёт новую точку, наблюдающую все предложенные варианты.

Корзина — значение записи с `deleted_at`; окончательное удаление — значение с `purged_at`. Эти маркеры и причинный контекст не истекают вместе с восемью файлами истории. Поэтому старая неизменённая версия не возвращает удалённую запись; старая изменённая ветка даёт конфликт. Категории имеют UUID; удалённая категория в локальном представлении оставляет записи без категории. Сами облачные значения не теряются при таком представлении.

## Публикация и доступ

Облачный payload: `protocol=1`, UUID `id`, `state`. Он шифруется конвертом PMVAULT под текущим доступом. Черновиков, локальных предпочтений, OAuth, имени устройства и локальной очереди в нём нет. Цвета категорий входят в state отдельными регистрами. Локальный документ получил необязательное поле `sync`; прежняя версия без поля читается как `sync=null`.

До отправки точные зашифрованные байты, UUID и идентификатор состояния сохраняются в локальной зашифрованной очереди. После неоднозначной ошибки повторяются те же байты/UUID. Ответ create недостаточен: байты читаются обратно, сравниваются с очередью и только затем подтверждение атомарно сохраняется. Более новые локальные изменения публикуются следующей версией, не подменяют уже отправленную. Обычная проверка без изменений не расходует восемь локальных состояний; служебное подтверждение заменяет актуальный файл поколения без вытеснения содержательных резервных состояний.

Заголовок и его хеш определяют доступ, включая обычную смену мастер-пароля. Неизвестный другой доступ или UUID хранилища останавливают публикацию. Загруженные исходники и локальная рабочая копия сохраняются отдельно зашифрованными в `sync-blocked`. Ранее проверенные байты старой эпохи можно учитывать как уже причинно интегрированные; их SHA256/вектор записаны в зашифрованных локальных метаданных. Неподтверждённая собственная очередь также причинно включена в актуальное локальное состояние.

Перенос старой ветки требует разблокировать источник и подтвердить объединение. Варианты одного UUID объединяются причинно; конфликты сохраняются. Для другого хранилища записи и варианты добавляются с новыми UUID, категории сохраняются; его удаления не применяются к локальным совпавшим UUID. Принятие доступа другого независимого хранилища запрещено. При принятии нового доступа того же хранилища обновляются все управляемые локальные копии; исходники остаются нетронутыми.

## Очистка и транспорт

Удаляемая совместимая версия должна иметь восемь отдельных причинно покрывающих её, более поздних по порядку `(сумма вектора, UUID)` свидетельств без конфликтов. Варианты неразрешённых конфликтов защищают внесшие их версии. Для уже интегрированных байтов прежнего доступа дополнительно проверяются точное совпадение SHA256, сохранённый вектор и восемь свидетелей текущего доступа; при любых текущих конфликтах такие файлы сохраняются.

Порядок строгий и не зависит от времени: каждое удаление направлено к восьми более высоким неизменяемым свидетелям. Для конечного набора его восемь максимальных элементов не могут быть удалены по этому правилу; причинное покрытие переносит сохранённые изменения через последующее удаление свидетелей. Проверены независимые клиенты и конкурирующие устаревшие списки очистки. Реальная согласованность Drive и гонки сети ещё требуют живой приёмки. Несовместимые/необработанные версии могут увеличивать фактическое количество файлов выше восьми.

Drive-объект получает заранее выделенный ID и приватные appProperties: приложение, UUID версии и собственный ID объекта. Ручная копия получает другой ID, поэтому не считается служебным объектом, даже если скопировались свойства. Удаление работает только с ID полного проверенного списка. Совпавший UUID версии с разными байтами останавливает обмен. Параллельно созданные папки приложения читаются вместе. Удалённая привязанная папка требует явного подтверждения повторной загрузки; отключение Google не удаляет Drive.

Ограничения: 4 МиБ на версию, 64 МиБ на чтение истории, 1000 версий, 4096 акторов, 50 000 регистров, 10 000 записей наблюдения в метаданных. При превышении — отказ без удаления данных. Рост причинного контекста намеренно не очищается эвристикой; для дальнейшего роста понадобится отдельная согласованная миграция.

Сетевые потоки получают только зашифрованные байты и доступ к DPAPI-подключению. Ключ хранилища не передаётся сетевой операции. Расшифровка/слияние и локальная фиксация выполняются в GUI-потоке. При блокировке выставляется cancellation; выполняющийся HTTP-запрос может завершиться в пределах timeout, но следующие запросы и применение результата прекращаются. Возобновление работает только после разблокировки. Тест проверяет отбрасывание результата после блокировки и исполнение callback в GUI-потоке.
