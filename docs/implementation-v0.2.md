## Реализованный результат

К локальному ядру 0.1 добавлены многозначные причинные регистры записей/категорий, устойчивые удаления, зашифрованная очередь с повтором точных байтов, подтверждение публикации обратным чтением, сохранение конфликтов и отдельный выбор варианта. Локальные черновики и настройки исключены из облачной версии. Служебный обмен без изменения данных не вытесняет содержательные локальные резервные состояния.

Drive v3 реализован напрямую через HTTPS: постраничный полный список, видимые папки, заранее выделенные ID, неизменяемые файлы, дубликаты/повторы, границы размера, отмена, ошибки API и безопасная очистка. Ручные копии исключаются привязкой ID объекта. Удалённая папка не воссоздаётся молча. Google отключается без удаления файлов; удаление служебных облачных версий — отдельное действие.

OAuth: Desktop app, системный браузер, PKCE S256, случайный state, callback только на 127.0.0.1 со случайным портом, три минуты ожидания, отказ от посторонних endpoints и журналирования callback. Токены и локальная привязка защищаются настоящей DPAPI текущего пользователя Windows, не экспортируются с паролями.

При неизвестном доступе публикация останавливается. Исходники сохраняются зашифрованными в `sync-blocked`; GUI позволяет разблокировать источник и подтвердить перенос. Для того же UUID хранилища пользователь может явно принять новый доступ, обновляя все управляемые копии; несовместимые изменения не теряются. Другое независимое хранилище добавляет записи с новыми UUID.

Интерфейс получил Google Drive, разрешение конфликтов и объединение файла. Сетевые потоки не получают ключ хранилища; при блокировке отменяются следующие запросы и отбрасывается поздний результат. Автоматический обмен повторяется примерно раз в минуту только в открытой сессии без незавершённого редактора/модального окна.

## Проверки

Актуальное число/результат: [JUnit](../artifacts/tests.xml), [вывод pytest](../artifacts/pytest.txt). Среда: Windows 11 x64 build 26300, CPython 3.14.6, PySide6 6.12.0, cryptography 50.0.2, argon2-cffi 25.1.0. [Манифест исходников](../artifacts/source-manifest.json), [входы тестов](../artifacts/test-inputs.json). Git-репозиторий пока не инициализирован, поэтому commit не выдумывается.

Проверены: логика/криптография 0.1, падения процесса, два/три независимых клиента на имитации транспорта, независимые правки, конфликт пароля, удаление против редактирования, поздний старый клиент после очистки, потеря подтверждения, повтор после перезапуска, переход доступа/перенос старой ветки, другое хранилище, ручные копии, неполный список, удалённая папка и отмена. Проверяются свойства слияния и устаревшие конкурирующие списки очистки.

Qt offscreen проверяет поля, черновик, таймеры, скрытый пароль, подменённый clipboard, импорт экспорта/восстановление и то, что поздний сетевой результат не применяется после блокировки. Callback проверен на GUI-поток. Обработчик нативного уведомления Windows выполняет блокировку синхронно до возврата; это проверено подачей синтетических MSG для lock/suspend, без блокировки рабочего стола пользователя или настоящего сна. Настоящая Windows DPAPI проверена сохранением, чтением, отсутствием уникального открытого маркера и удалением файла подключения. Это не фиктивное шифрование OAuth в тестах.

## Сборка и поставка

PyInstaller 6.22.3 собирает переносимый EXE с библиотеками. [Журнал сборки](../artifacts/build.log), [соответствие входов сборки](../artifacts/build-receipt.json), [состав Qt](../artifacts/bundle-audit.json). Скрипт сверяет хеши входов до/после сборки и отказывается подтверждать результат при изменении исходников во время сборки.

[Проверочный запуск EXE](../artifacts/frozen-smoke/smoke-result.json) выполняется через `--self-test` на отдельном временном хранилище, с PATH только на System32, без PYTHONPATH/PYTHONHOME, без прав администратора. Проверяется загрузка зависимостей из `_internal`, сохранение/повторное чтение, восстановление, Qt render и блокировка/разблокировка. Это работа собранного процесса, а не запуск исходников. Это также не чистая VM: Python установлен на этой Windows, хотя процесс его не использует.

После просмотра снимка исправлено отсутствие кириллицы в offscreen font database: проверочный запуск явно подключает системный Segoe UI. Используется русский перевод стандартных Qt-диалогов. Ненужные плагины Virtual Keyboard/PDF и DLL QML/Quick исключены; по графу PE остаются только Qt Core/GUI/Widgets/Network. Лицензии и соответствующие исходники Qt Base, Qt Translations и PySide Setup/Shiboken входят в подготовку ZIP.

Архив и его SHA256 создаёт `scripts/package_release.py` в `releases`; архив нигде не публикуется. `scripts/check_release.py` сверяет все внутренние SHA256, распаковывает точный архив в отдельную папку build и выполняет его собственный EXE на вымышленном хранилище с очищенным PATH. Результат сохраняется отдельно в `artifacts/release-audit.json`. Установщик, автозапуск, службы и изменения реальных пользовательских паролей не выполнялись. - Реальный OAuth/Drive и два реальных подключённых компьютера: нет OAuth-проекта. [Инструкция настройки](google-setup.md) готова. Имитация API не объявляется живой приёмкой.
- Чистая Windows без Python, физическая блокировка сеанса/сон, реальный clipboard и полная ручная навигация GUI. Их нельзя вывести из offscreen/подменённых проверок. Независимый аудит безопасности не выполнялся.
- [Сценарий десяти слайдов](presentation.md) подготовлен; PPTX не экспортирован, потому что требуемый навыком Presentations `@oai/artifact-tool` отсутствует и в shell, и в Node runtime. Подмена его запрещённым этим навыком авторингом python-pptx не выполнялась.

Все доступные локальные шаги продолжаются без дополнительных пользовательских вопросов. Внешние проверки и экспорт PPTX остаются явно отделёнными от выполненной реализации. Сайт отложен. Текущая версия — кандидат для испытаний на вымышленных данных, не завершённый безопасностный выпуск.

## Сохраняющиеся ограничения

Повреждённый CURRENT требует ручной диагностики. Невозможность сохранить черновик при блокировке явно сообщается и может потерять незавершённый ввод. Экспорты и исходники в `damaged-*`/`sync-blocked` требуют прежних секретов и не входят в автоматическую ротацию. Неудачная очистка после фиксации может оставить старые поколения. Случайные nonce и тестовые векторы не заменяют независимый аудит; обесточивание и аппаратные отказы не проверены. Конечные пределы причинного контекста задокументированы в [протоколе](sync-protocol.md).
