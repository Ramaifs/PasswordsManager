# План разработки менеджера паролей

Дата: 2026-10-25. Основание: ответы пользователя Q1–Q48.

Статус: подготовлена настольная версия 0.2.1, код синхронизации и самостоятельный EXE. После неё пользователь поручил начать сайт с созданием хранилища как в Obsidian. Первая веб-версия реализована отдельно: [протокол](docs/web.md). Настольные ограничения — в [протоколе 0.2](docs/implementation-v0.2.md); OAuth-проект, реальный Drive и чистая VM всё ещё не приняты. Прежнее откладывание сайта ниже относится к границам первой настольной версии; позднее указание пользователя разрешает отдельный веб-этап.

## 1. Цель и границы версии

Создать настольный менеджер настоящих паролей для Windows x64 на Python и PySide6. Личное зашифрованное хранилище работает без интернета; по желанию пользователь подключает свой Google Drive для синхронизации между компьютерами. Отдельный сервер приложения не нужен.

Первая законченная версия включает генератор, управление записями и категориями, поиск, шифрование, мастер-пароль, восстановление доступа, резервные копии, импорт прежнего JSON, зашифрованный экспорт и Google Drive. Сначала завершается локальная работа, затем синхронизация.

Сайт, двухфакторная аутентификация, совместный доступ, несколько независимых хранилищ одного пользователя и открытый экспорт JSON/CSV отложены на следующие версии. Установленного срока нет.

## 2. Проверенное исходное состояние

Репозиторий [Ramaifs/Passwords-Manager](https://github.com/Ramaifs/Passwords-Manager) проверен через GitHub connector на commit [`eab2103453ddca4e3dadf2998130bddca544eb76`](https://github.com/Ramaifs/Passwords-Manager/commit/eab2103453ddca4e3dadf2998130bddca544eb76). В нём три файла: `HardPassGenerator.py`, `PasswordManager.py`, `README.md`.

Это два отдельных консольных скрипта. Шифрование, мастер-пароль, GUI и синхронизация отсутствуют; менеджер записей существенно не завершён. Генератор использует `random` и сдвигает результат по Unicode, нарушая выбранные алфавиты. Обнаружены ошибки загрузки платформ, общих изменяемых объектов и открытого вывода данных. Подробности и ссылки: [проверка исходников](docs/baseline.md).

На момент планирования локальная папка содержала документацию без исходников приложения. При начале реализации подтверждены CPython 3.14.6/Windows x64, создана `.venv`, зависимости закреплены. Новый код написан самостоятельно, исходники исходного проекта не клонировались.

## 3. Записи и интерфейс

У пользователя одно личное хранилище. Каждая запись получает устойчивый внутренний идентификатор и содержит:

| Поле | Требование |
| --- | --- |
| Название | Обязательно; одинаковые названия допускаются |
| Сайт | Необязательно |
| Логин | Необязательно |
| Почта | Отдельное необязательное поле |
| Телефон | Отдельное необязательное поле |
| Пароль | Необязательно; скрыт до явного действия пользователя |
| Категория | Одна плоская категория либо «Без категории» |
| Заметка | Необязательно |

Несколько аккаунтов одного сервиса — разные записи. Категории можно создавать, переименовывать и удалять; удаление категории переводит её записи в «Без категории». Поиск работает по названию, сайту, логину, почте и заметке; есть фильтр по категории. Раздельные поля логина, почты и телефона сохраняют данные импорта.

Интерфейс русский. Слева категории и корзина, в центре поиск и список, справа просмотр и редактирование записи. Генератор и настройки доступны отдельными кнопками. Поддерживаются светлая и тёмная темы; по умолчанию используется системная тема.

Изменения записи подтверждаются кнопкой «Сохранить». При уходе из редактора предлагаются сохранение или отмена. Перед автоматической блокировкой незавершённые изменения сохраняются в зашифрованный локальный черновик; после разблокировки редактирование можно продолжить. Черновики не синхронизируются и не считаются подтверждёнными изменениями записи.

## 4. Генератор

- Длина по умолчанию — 20 символов; допустимый диапазон — 8–128.
- Выбираются строчные и прописные латинские буквы, цифры и спецсимволы; доступно исключение похожих символов.
- Можно получить несколько паролей. По уточнению пользователя настройки генератора запоминаются в памяти текущего запуска; генерация не сохраняет хранилище и не синхронизируется с Google.
- Каждый результат содержит символы всех выбранных групп и только из разрешённого набора.
- Генератор доступен отдельно и внутри создания/редактирования записи.
- Используется `secrets`; прежние сдвиги Unicode и алгоритм на `random` не переносятся.
- Некорректные настройки отклоняются с понятным сообщением; секреты не попадают в диагностический вывод.

## 5. Защита и восстановление доступа

Выбраны `cryptography`, Argon2id для получения ключа из мастер-пароля и AES-256-GCM для шифрования с проверкой целостности. Защищаются все поля записей, категории, корзина и черновики. JSON допустим как внутреннее представление данных перед шифрованием; открытого файла с содержимым хранилища приложение не создаёт.

Мастер-пароль — от 8 до 128 символов; разрешены пробелы и кириллица, поддерживаются парольные фразы. Обязательная комбинация классов символов и календарная смена не требуются.

При создании хранилища выпускается отдельный ключ восстановления. Приложение показывает его, предлагает сохранить или распечатать отдельно и просит подтвердить сохранение. Автоматического помещения ключа рядом с хранилищем или в Google Drive нет. Восстановление требует файла хранилища и ключа, после чего задаётся новый мастер-пароль.

При обычной смене мастер-пароля проверяется текущий пароль; ключ восстановления сохраняется. При аварийной замене ключа восстановления меняется также ключ шифрования данных и заново шифруется актуальное хранилище. Остальные компьютеры должны обновить доступ.

В обоих случаях защита восьми управляемых локальных резервных копий обновляется под актуальные данные доступа. Вручную экспортированные файлы не изменяются и могут требовать прежних секретов; приложение сообщает об этом до операции.

Автоматическая блокировка: 30 минут бездействия в приложении, блокировка Windows или переход в сон. Интервал настраивается. После перезапуска хранилище всегда заблокировано. При блокировке синхронизация приостанавливается до разблокировки.

Показ и копирование пароля требуют явного действия. Через 5 минут очищается текущий буфер обмена, если в нём всё ещё находится пароль, скопированный приложением.

Основные сценарии защиты — кража файла, посторонний доступ к Google Drive и доступ к заблокированному приложению. Защита от заражённой Windows, читающей ввод и память приложения, не входит в заявленные гарантии. Очистка текущего буфера не означает удаления из истории Windows или сторонних программ. Смена секретов не меняет ранее скачанные чужие копии; отключённое устройство узнаёт об изменении доступа после подключения. При утрате мастер-пароля и ключа восстановления серверного способа разблокировки нет.

Параметры Argon2id, версия формата, структура защищённого заголовка и порядок смены ключей будут зафиксированы до работы с пользовательскими данными и проверены отдельно. Уникальность nonce, проверка целостности, ограничение размеров и параметров недоверенного файла, отказ от открытого хранения секретов и безопасное завершение операций входят в технические требования реализации. Выбор алгоритмов сам по себе не является доказательством безопасности готового приложения. [Решение о шифровании](docs/adr/0006-vault-cryptography.md).

## 6. Локальное хранение, удаление и импорт

Данные и настройки находятся в папке данных текущего пользователя Windows, отдельно от программы. Локальное сохранение должно переживать ошибки записи и прерывание процесса без потери последнего успешного состояния. Приложение хранит 8 последних успешных зашифрованных состояний. При повреждении исходный файл сохраняется; предлагается восстановление из резервной копии.

Удалённые записи остаются в зашифрованной корзине 30 дней; доступны восстановление и отдельное окончательное удаление. Окончательное удаление относится к актуальному состоянию: прежние резервные копии и экспортированные файлы могут содержать старые данные. Механизм синхронизации должен помнить факт удаления, чтобы давно отключённое устройство не возвращало запись молча.

Перед восстановлением резервного состояния показываются различия и сохраняется текущее состояние. Подтверждённое восстановление становится новым изменением для синхронизации.

Импорт старого JSON: корневой объект «название платформы → список аккаунтов». Соответствие полей:

| Старое поле | Новая запись |
| --- | --- |
| Название платформы | Название записи |
| `Username` | Логин |
| `Email` | Почта |
| `Phone` | Телефон |
| `Password` | Пароль |
| Отсутствующие сайт и заметка | Пустые значения |
| Отсутствующая категория | «Без категории» |

Импорт выполняется после предварительного просмотра и подтверждения, исходный файл не меняется. Исходные файлы и предпросмотр не печатаются в журналы. Ошибочные строки и неожиданный формат не должны приводить к молчаливой потере полей или перезаписи текущего хранилища. Для проверки используются собственные вымышленные примеры этой схемы. Экспорт первой версии — зашифрованный.

## 7. Google Drive

Подключение добровольное; локальная работа доступна без Google. Настраивается один OAuth-проект разработчика. Пользователь нажимает «Подключить Google» и подтверждает доступ в системном браузере. До выпуска готовятся необходимые настройки OAuth и учитываются ограничения Testing. Разрешения выбираются для файлов приложения; защищённое хранение и удаление локальных токенов проверяются отдельно. OAuth предоставляет доступ к Drive и не заменяет мастер-пароль.

Приложение напрямую работает с отдельной видимой папкой в Drive. Передаются зашифрованные версии; пользователь может самостоятельно скачать копию. Сделанные без интернета изменения сохраняются локально и ожидают синхронизации; интерфейс показывает её состояние.

Изменения публикуются отдельными зашифрованными версиями. Протокол должен выявлять параллельные изменения, подтверждать успешную публикацию и сохранять данные при сбое сети или приложения. Выбор по времени изменения не используется для молчаливого разрешения конфликтов.

- Разные записи объединяются автоматически.
- Для конфликтов одной записи сохраняются варианты до выбора пользователя.
- Одновременные удаление и редактирование считаются конфликтом.
- При обнаружении другого облачного хранилища исходные копии сохраняются; объединение требует подтверждения и разблокировки обоих.
- Изменения устройства со старым доступом сохраняются отдельно зашифрованными. Их загрузка останавливается; перенос требует разблокировки старой и актуальной версий и подтверждения объединения.
- Одновременная смена ключей сохраняет обе версии до явного разрешения конфликта.

В облаке сохраняются 8 последних успешно объединённых состояний. Конфликтующие и ещё не обработанные версии остаются до разрешения ситуации: поэтому фактическое количество файлов может превышать 8. Очистка касается только служебных версий приложения; вручную сделанные копии сохраняются. Удаление старых версий допускается только после проверки, что они не нужны для сохранения или разрешения неучтённых изменений. [Архитектурное решение](docs/adr/0007-drive-versions.md).

При отключении Google синхронизация останавливается и сохранённые данные подключения удаляются. Локальное хранилище и уже записанные в Drive данные сохраняются. Удаление облачной копии — отдельное подтверждаемое действие. Если папка удалена через Drive, локальное хранилище сохраняется; повторная загрузка предлагается с подтверждением.

## 8. Поставка и условия

Архив Windows x64 содержит запускаемый `.exe` и библиотеки рядом. Пользователю не нужны установка Python и права администратора. Проверяется работа именно собранного приложения, включая зависимости, Qt-плагины и сохранение данных отдельно от каталога программы.

Для собственного кода выбраны All Rights Reserved и разрешение бесплатных установки и использования готовой программы. Права на сторонние библиотеки сохраняются по их лицензиям. До распространения проверяются права на использованный исходный код, лицензии фактических зависимостей и соблюдение условий LGPL, готовятся тексты условий и уведомления. Отсутствие лицензии в исходном репозитории не является разрешением перелицензировать чужой код.

## 9. Этапы реализации

| Этап | Результат и проверяемый выход |
| --- | --- |
| 1. База и среда | Зафиксированный исходный commit, доступная среда Python, зависимости, воспроизводимый запуск; собственные фикстуры без настоящих секретов |
| 2. Локальное ядро | Модель записей, генератор, создание/разблокировка/сохранение зашифрованного хранилища, восстановление доступа и 8 резервных состояний; проверки повреждения и прерывания записи |
| 3. Настольный интерфейс | PySide6, управление записями и категориями, поиск, темы, генератор, сохранение/черновики, блокировка, буфер обмена, корзина и восстановление |
| 4. Совместимость и секреты | Импорт прежней схемы, зашифрованный экспорт, смена мастер-пароля и ключа восстановления, обновление управляемых копий; проверка отсутствия открытых секретов в артефактах и журналах |
| 5. Синхронизация | OAuth, видимая папка, версии, очередь изменений, конфликты, старые устройства и безопасная очистка; проверки двух независимых клиентов, затем реального Drive |
| 6. Поставка и материалы | Проверенный архив `.exe`, условия и уведомления, инструкция, зависимости, CHANGELOG, таблица фактических проверок, демонстрационные данные, текстовая работа и презентация |

Новые функции и завершённые исправления отражаются в `CHANGELOG.md` с датой и доказательствами проверки. Журнал событий приложения, если появится, не содержит паролей, мастер-пароля, ключей, OAuth-токенов или содержимого хранилища.

## 10. Приёмка и материалы

Готовность подтверждают автоматические проверки основной логики, ручная проверка собранного `.exe` и реальная синхронизация двух независимых клиентов на вымышленных данных. Уровни «исходники проверены», «реализовано», «тесты пройдены», «архив собран», «проверено в Windows» и «проверено с реальным Google Drive» фиксируются отдельно. Непроверенный сценарий не записывается как успешный.

Исходная матрица: [docs/verification.md](docs/verification.md). Первые автоматические результаты добавлены отдельно; все строки целиком ещё не приняты.

Итоговый комплект: исходники с зависимостями и инструкцией запуска, архив приложения Windows, CHANGELOG, техническое описание, таблица проверок и вымышленные демонстрационные данные. Для 0.2.1 подготовлены исходники, EXE, сценарий архивации, инструкции, описание форматов, тесты, лицензии/исходники библиотек и техническая работа. Сценарий презентации подготовлен; PPTX не экспортирован из-за отсутствующего presentation runtime. Реальная облачная и ручная приёмка остаются отдельной обязательной работой.
